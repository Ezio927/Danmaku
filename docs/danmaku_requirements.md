# Bilibili 直播弹幕机需求分析（MosCow）

> 版本：v1.01  
> 状态：粗略确认核心需求；临时暂定参数在实现前复核  
> 平台：Windows 10/11 x64  
> 用途：主播监看弹幕并通过 OBS 展示

## 1. MVP 范围

首版必须提供：

- Bilibili 直播开放平台接入；
- 紧凑主播监看窗口；
- OBS 透明弹幕页面；
- 普通/表情弹幕、付费礼物、上舰、醒目留言；
- OBS 用户、关键词和礼物金额过滤；
- 礼物合并、醒目留言置顶及删除处理；
- 心跳、断线重连、高流量保护；
- 托盘、配置保存、日志、模拟消息和脱敏诊断；
- Windows 标准安装包。

首版不做：

- 自动回复和弹幕命令；
- 历史消息持久化；
- TTS 和提示音；
- 关注、进场、点赞、在线人数；
- 多房间、多平台、多主播；
- 多主题、自定义 HTML、样式导入导出；
- 全自动更新和免安装版本。

## 2. 开放平台与连接

### 2.1 凭证

- 首次配置 App ID、Access Key ID、Access Key Secret；
- Secret 使用 Windows 安全凭据存储，界面默认遮挡；
- 每场直播重新粘贴身份码；身份码只保存在内存中，不跨重启保存；
- 应用正常停止或退出时结束开放平台场次。

### 2.2 连接状态

状态至少包括：

```text
未配置 → 等待身份码 → 启动场次 → 连接中 → 已连接 → 重连中
```

- 提供停止接收和重新连接；
- 网络异常自动退避重连；
- 身份码明确失效时停止盲目重试并要求重新输入；
- 区分凭证错误、身份码错误、未开播、网络错误和平台异常；
- 主播窗口分别显示 Bilibili、本地服务和 OBS 状态。

## 3. 主播窗口

### 3.1 窗口形态

- 使用紧凑单列窗口，不建设完整直播控制台；
- 显示房间信息、连接状态、醒目留言置顶区和消息时间线；
- 支持窗口缩放、始终置顶和透明度；置顶与透明度默认关闭；
- 记住窗口位置、尺寸和显示设置；
- 关闭按钮默认隐藏到托盘，可改为直接退出或每次询问；
- 托盘提供显示窗口、停止/连接、设置和退出。

### 3.2 时间线

- 主播窗口显示全部受支持消息，不应用 OBS 过滤；
- 向上滚动后暂停跟随最新消息，但继续接收；
- 暂停期间显示新增消息数量；点击提示或滚到底部后恢复跟随；
- 内存中保留最近 1000 条，超过后淘汰最旧消息；
- 支持清空主播当前视图；
- 消息右键菜单支持复制内容、复制用户名、加入 OBS 用户屏蔽名单及查看详情。

## 4. 消息规则

| 消息 | 主播窗口 | OBS |
| --- | --- | --- |
| 普通弹幕 | 显示 | 显示 |
| Bilibili 表情弹幕 | 显示 | 显示 |
| 付费礼物 | 显示 | 金额达到阈值时显示 |
| 上舰 | 显示 | 显示 |
| 醒目留言 | 时间线＋展开置顶 | 彩色时间线卡片＋紧凑顶部摘要 |
| 连接状态 | 显示 | 不显示 |

统一消息至少包含：

- 消息类型、消息 ID、接收时间和平台时间；
- 用户稳定标识、用户名、头像和身份；
- 粉丝牌、舰队或房管信息；
- 类型特有字段，如正文、礼物 ID、数量、金额和醒目留言有效期；
- 原始事件引用或必要的原始字段，供诊断和未来扩展。

## 5. 醒目留言

### 5.1 主播侧

- 同时进入普通时间线和顶部展开区；
- 顶部一次展开一条，优先最早尚未展示的消息；
- 新消息不强制打断当前内容，显示待查看数量；
- 可手动查看上一条和下一条；
- 暂定完整显示 3 秒后标记为“已展示”，不表示主播已经读完；
- 置顶到期只退出顶部，完整卡片继续留在时间线。

### 5.2 OBS 侧

- 完整醒目留言在收到时进入普通时间线；
- 顶部只显示头像、金额、档位颜色和剩余进度，不展开正文；
- 多个摘要横向排列且不换行，空间不足时裁剪最旧项；
- 主播侧的选择和切换不影响 OBS。

### 5.3 删除

- 收到删除事件后，立即移除 OBS 卡片、顶部摘要和主播置顶项；
- 主播时间线保留灰色“该醒目留言已被删除”记录及必要上下文；
- 灰色记录随主播窗口内存上限正常淘汰。

## 6. 礼物

- 仅考虑付费礼物；OBS 默认最低金额为 0.1 元，可调整；
- 金额阈值不影响醒目留言和上舰；
- 主播窗口与 OBS 均合并连送礼物；
- 优先使用平台连送/组合标识和累计字段；
- 缺少可靠平台标识时，按“房间＋用户稳定标识＋礼物 ID”合并；
- 备用合并窗口为距离上次同类礼物不超过 5 秒，每次新礼物延长窗口；
- 合并时更新数量和总金额，只播放轻量更新动效；
- 不合并不同用户、不同礼物、上舰或醒目留言。

## 7. OBS 页面与样式

### 7.1 布局

- 提供固定本地 URL，只监听 `127.0.0.1`；
- 页面透明、底部对齐、自动向上滚动，不显示滚动条；
- 浏览器源高度自然决定同屏数量，不使用主播可见的最大条数配置；
- 调整高度不得缩放字体、头像、间距或卡片；
- 调整宽度时允许文本自然换行；
- 超出顶部的消息直接裁剪。

### 7.2 样式

- 首版只提供 YouTube 经典主题；
- 普通弹幕采用纯文字和高对比描边，不提供气泡底色；
- 支持字体、字号、行高、描边、头像及粉丝牌/徽章显隐；
- 支持分别修改普通用户、舰队、房管和主播用户名颜色；
- 礼物、上舰和醒目留言使用预设彩色卡片；
- 金额档位颜色首版不可逐档编辑；
- 设置页提供四种核心消息的实时模拟预览；
- 修改设置后自动保存并实时同步到已连接 OBS 页面。

### 7.3 多来源、重连与快照

- 多个 OBS 来源共享消息、样式和过滤规则，但根据各自宽高独立排版；
- 单个 OBS 来源断开不影响主播窗口和其他来源；
- 页面晚启动或重新连接时自动取得当前快照；
- 快照暂定为最近 5 分钟且最多 100 条过滤后消息；
- 恢复仍有效的醒目留言摘要和未结束的礼物合并状态；
- 快照静态出现，不重播旧消息动画；新消息正常播放动画；
- 弹幕机异常或页面重连时 OBS 保持透明，不显示错误信息。

### 7.4 清屏

- 主播窗口提供“清空 OBS 画面”；
- 清除 OBS 普通消息、礼物卡片及对应快照；
- 不清空主播时间线、不修改过滤规则、不停止平台连接；
- 默认保留仍有效的醒目留言；二级操作可连同醒目留言一起清除。

## 8. OBS 过滤

### 8.1 用户

- 优先按开放平台稳定用户标识屏蔽，并保存当前昵称用于展示；
- 无稳定标识时才退化为昵称匹配；
- 命中用户的弹幕、表情、礼物、上舰、醒目留言和顶部摘要均不进入 OBS。

### 8.2 关键词

- 一行一个关键词，去除首尾空格、忽略空行并去重；
- 英文字母不区分大小写，按正文包含关系匹配；
- 只匹配普通/表情弹幕正文和醒目留言正文；
- 不匹配用户名、礼物名、上舰标题或系统状态；
- 命中后隐藏整条消息，首版不支持正则表达式。

### 8.3 生效行为

- 过滤必须在消息分发给 OBS 前完成，OBS 不得收到未过滤正文；
- 新增规则立即阻止后续消息，并移除 OBS 当前可见的匹配内容；
- 解除规则只影响后续消息，不恢复已经移除的旧内容；
- 被 OBS 过滤的消息在主播窗口保留，可显示轻量状态标记；
- 规则本地自动保存，并提供测试文本是否命中的功能。

## 9. 高流量与性能

- 主播窗口不人为减速，采用批量 UI 更新和虚拟列表；
- OBS 普通弹幕使用有界平滑队列；正常逐条显示，高流量时缩短间隔，极高流量时减少动画或批量推进；
- 醒目留言、礼物和上舰可以绕过普通弹幕队列立即显示；
- 普通弹幕彼此保持顺序；允许付费互动在 OBS 中超越普通弹幕；
- 过载时只淘汰最旧的未展示普通弹幕，不主动淘汰礼物、上舰或醒目留言；
- 压力目标：持续 20 条/秒、峰值 100 条/秒时主播窗口仍可操作；
- 正常流量下本地附加延迟 P95 目标小于 300ms；
- 连续运行至少 8 小时，内存不得持续无界增长。

初始调度参数：普通动画约 200ms、最快约 80ms、待展示队列最多 200 条、预计延迟超过约 5 秒时开始淘汰。这些数值须经压力测试调整。

## 10. 配置、安全与诊断

- 配置带版本号，采用临时文件和原子替换，并保留一个上次有效备份；
- 配置损坏时尝试恢复，失败后进入安全默认配置；
- 同时只运行一个主实例；第二次启动唤醒已有窗口；
- 使用固定默认端口；冲突时停止本地服务并提示，不静默切换端口；
- 修改端口后提示同步更新 OBS URL；
- 默认日志不记录完整弹幕正文或敏感字段；
- 身份码、Secret、Cookie 和完整用户标识必须脱敏；
- 日志暂定单文件 10 MB，保留最近 5 个；
- 提供本地脱敏诊断包，由主播决定是否分享；
- 诊断包包含版本、Windows 信息、三层连接状态、端口、OBS 连接数、脱敏配置和近期日志；
- 诊断包不包含弹幕正文、完整用户标识、身份码、Secret、Cookie 或 OBS 场景信息；
- 提供普通弹幕、礼物、上舰和醒目留言模拟事件，不发送到 Bilibili。

## 11. 安装与升级

- 提供 Windows 10/11 x64 标准安装包，打包全部运行环境；
- 默认当前用户安装，尽量不要求管理员权限；
- 开机启动可选且默认关闭；自动启动时隐藏到托盘并等待身份码；
- MVP 只检查并提示新版本，由用户手动安装；直播过程中不得自动升级或重启；
- 升级保留配置、过滤规则和安全凭据，并执行带备份的配置迁移；
- 卸载时询问保留配置或删除全部本地数据；
- 升级后默认端口、OBS URL 和核心路由保持稳定。

## 12. MVP 验收摘要

MVP 完成时至少满足：

1. 安装、首次凭证验证、每场身份码连接和正常结束场次可用；
2. 主播窗口正确显示五类核心消息，支持暂停跟随、回看、置顶和托盘；
3. OBS 页面透明、响应式、可重连，并正确显示 YouTube 经典样式；
4. 醒目留言的双端置顶、到期和删除行为符合要求；
5. 礼物金额阈值和连送合并计算正确；
6. OBS 用户及关键词过滤不会泄露未过滤正文；
7. 网络中断可自动恢复，身份码失效时给出明确提示；
8. 高流量只允许淘汰未展示普通弹幕；
9. 模拟消息、三层状态、OBS 连接数和脱敏诊断可用；
10. 通过 8 小时稳定性测试，日志和诊断中无敏感凭证。

## 13. 实施前复核项

| 项目 | 暂定值或行为 |
| --- | --- |
| 醒目留言已展示判定 | 展开约 3 秒后标记为已展示 |
| OBS 快照 | 最近 5 分钟且最多 100 条 |
| OBS DOM 安全上限 | 100 条 |
| 礼物备用合并窗口 | 5 秒滑动窗口 |
| OBS 动画间隔 | 常规约 200ms，最快约 80ms |
| OBS 普通消息队列 | 200 条或预计延迟约 5 秒 |
| 主播回看缓冲 | 最近 1000 条 |
| 日志轮转 | 10 MB × 5 |
| 本地固定端口 | 技术设计阶段确定 |
| 开放平台申请与字段 | 登录当前官方平台后验证 |

## 14. 后续优先级

### Should

- 重要事件提示音；
- 更多 OBS 过滤规则；
- 应用内升级和体验优化。

### Could

- 历史消息、礼物和场次记录；
- TTS、统计和辅助事件；
- 样式预设及导入导出；
- 简化插件接口；
- 其他平台、房间或部署形态。
