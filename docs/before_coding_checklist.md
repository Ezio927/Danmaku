# 开发前的设计工作清单

按以下顺序准备设计文档。

```text
需求分析
  ↓
界面线框图
  ↓
体系结构设计（架构文档＋ADR）
  ↓
详细设计（模块、消息、协议、配置、时序）
  ↓
迭代与测试计划
  ↓
编码
```

## 1. 界面线框图

产出 `docs/ui-wireframes.md`，定义：

- 紧凑主播窗口；
- 首次配置及身份码连接页；
- OBS 样式设置与模拟预览；
- OBS 过滤设置；
- 错误状态和诊断界面。

线框图只确定布局、操作入口和状态变化，不要求视觉精稿。

## 2. 架构文档

产出 `docs/architecture.md`，至少定义：

- 系统边界和运行进程；
- 桌面窗口、本地服务、OBS 页面与 Bilibili 的关系；
- 消息接入、标准化、合并、过滤和分发链路；
- 配置、凭据、日志和诊断数据的存储位置；
- 故障隔离、安全边界、安装和部署方式；
- 核心模块及其依赖关系。

可以包含系统上下文图、进程/容器图、组件图和消息流图，按需绘制。

## 3. ADR 架构决策记录

在 `docs/adr/` 中为重要技术选择定义：

- 桌面框架与前端技术；
- 后端语言及单进程/多进程方案；
- Bilibili 直播开放平台接入；
- OBS 本地通信方式；
- 内部事件模型；
- 配置和 Secret 存储；
- Windows 安装与升级。

每份 ADR 记录背景、最终决策、备选方案、理由、后果和状态。

## 4. 详细设计

产出 `docs/detailed-design.md`，定义：

- 职责与边界；
- 输入、输出和依赖；
- 生命周期与持有状态；
- 并发方式和错误处理；
- 可测试接口。

重点模块包括连接适配器、消息标准化、事件总线、礼物合并、OBS 过滤、OBS 投影、主播消息缓冲、醒目留言管理、配置、凭据和诊断服务。

类图按需绘制。技术栈确定前不必设计大量具体类，优先使用模块图和依赖图。

## 5. 消息模型

产出 `docs/message-model.md`，定义：

- 普通/表情弹幕、礼物、上舰、醒目留言及删除事件；
- 系统状态、消息更新、消息删除和 OBS 快照；
- 消息 ID、用户稳定标识、金额单位和时间字段；
- 平台原始事件到内部标准消息的映射；
- 消息的版本兼容和扩展规则。

## 6. API 与本地协议

产出 `docs/api-protocol.md`，定义：

- HTTP API 和 WebSocket/SSE 通信方式；
- 主播窗口与 OBS 页面的连接流程；
- 快照、增量消息、更新、删除和清屏；
- 样式与过滤配置同步；
- 心跳、错误结构和 `protocolVersion`；
- OBS 重连、恢复及多来源行为。

## 7. 配置设计

产出 `docs/configuration-schema.md`，定义：

- 带 `configVersion` 的配置结构；
- 应用、窗口、OBS、样式和过滤配置；
- 普通配置文件与 Windows 安全凭据的边界；
- 默认值、校验、备份和版本迁移规则。

MVP 不保存历史消息，因此暂时不需要业务数据库和 ER 图。历史记录进入开发范围后再补数据库设计。

## 8. 关键时序图

可放入架构或详细设计文档，至少定义：

- 首次配置与凭证验证；
- 使用身份码启动和结束场次；
- 消息进入主播窗口和 OBS；
- OBS 过滤与礼物合并；
- 醒目留言置顶、到期和删除；
- OBS 重连与快照恢复；
- Bilibili 断线重连；
- 正常退出和异常恢复。

## 9. 测试

产出 `docs/test-plan.md`：

- 将 MVP 拆成可独立验收的里程碑；
- 为每个里程碑列出完成条件；
- 规划单元、协议、集成、压力、长时间运行和安装测试；
- 建立 Mock 消息源，覆盖四种核心消息和异常事件；
- 明确需求中暂定参数的验证时机。
