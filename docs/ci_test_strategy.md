# CI 与测试策略

## 测试分层

### 1. 单元测试

随对应模块一同开发，优先覆盖：

- Bilibili 原始事件到内部消息的标准化；
- OBS 用户、关键词和金额过滤；
- 礼物连送标识及 5 秒备用合并窗口；
- 醒目留言置顶、到期、切换和删除状态；
- 主播回看缓冲与 OBS 快照边界；
- 配置默认值、校验、备份和版本迁移。

### 2. 协议测试

- 快照、增量、更新、删除和清屏事件；
- 样式及过滤规则同步；
- `protocolVersion` 兼容；
- 错误响应结构；
- 未过滤正文不得发送给 OBS。

### 3. 集成测试

使用 Mock Bilibili 消息源验证：

- 场次启动、心跳、结束和身份码失效；
- 网络断开与自动重连；
- 多个 OBS 来源同时连接；
- OBS 重连与快照恢复；
- 付费互动绕过普通弹幕队列。

### 4. UI、性能与发布测试

- 主播窗口暂停跟随和恢复到底部；
- OBS 在不同宽高下的响应式布局；
- 主播侧与 OBS 侧醒目留言表现；
- 持续 20 条/秒、峰值 100 条/秒；
- 8 小时稳定运行；
- Windows 安装、卸载、升级和安全凭据存储。

## CI 执行范围

### 每次 Push / Pull Request

- 空白与基础仓库检查；
- 快速单元测试；
- 协议测试；
- 必要的短集成测试。

### 定时或发布前

- 压力和长时间运行测试；
- Windows 安装及升级测试；
- 完整端到端测试。

## 平台策略

- 与平台无关的核心逻辑优先在 Ubuntu runner 运行；
- Windows 专属功能加入后增加 Windows runner；
- 当前没有 `tests/` 时 CI 明确跳过，开始编码后测试必须与功能同步提交；
- 不添加只为让 CI 通过而存在的占位测试。

## 分支要求

- `dev` 可以在本地验证后手动推送，Push 自动运行 CI；
- `main` 只通过 Pull Request 更新；
- 新 CI 首次在远端成功运行后，将 `Python tests` 设为 `main` 的必需状态检查。
